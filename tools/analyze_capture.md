# Offline Saleae capture checker

`analyze_capture.py` reads raw digital binary exports without accessing the BBG,
Saleae device, or Logic application. It needs a modern host Python and NumPy,
not the BBG's Python 3.2. The tested host versions are Python 3.12.14 and
NumPy 2.3.5. Run from the repository root; the following Windows setup uses
an installed Python 3.12 launcher and requires no PowerShell activation script:

```powershell
py -3.12 -m venv .venv
$py = '.\.venv\Scripts\python.exe'
& $py -m pip install -r requirements-bench.txt
New-Item -ItemType Directory -Path build -Force | Out-Null
& $py tools/analyze_capture.py CAPTURE_DIR --mode legacy --json build/legacy-analysis.json
& $py tools/analyze_capture.py CAPTURE_DIR --mode dld --config config/panel.example.json --colors 12AB34 --expected-frames 3 --bank-order --json build/dld-analysis.json
& $py tests/test_analyze_capture.py
```

Replace `CAPTURE_DIR` with the actual six-channel export directory. On Linux
or macOS, create the venv with `python3 -m venv .venv` and use
`.venv/bin/python` in place of `$py`. The pinned
[bench requirements](../requirements-bench.txt) also include
`logic2-automation` for optional live acquisition; the offline checker itself
imports only NumPy and the Python standard library. Neither this analysis
command nor its tests requires Logic 2, a connected analyzer, root, or SSH.
Installing host analysis packages is separate from the package-free native
BBG driver build. Raw bench captures are separate artifacts and are not
generated by these commands.

The directory must contain six files named `digital_0.bin` through
`digital_5.bin`. Use `--channels 2,0,1,3,4,5` to specify another mapping. These
six arguments are always in string order: P8_8, P8_10, P8_12, P8_14, P8_16,
P8_18. The raw files remain unchanged. Keep the `.sal` file and acquisition
metadata (sample rate, digital threshold, physical wiring, elapsed acquisition
time, application/device versions, and commanded sends) alongside the exports.

## Format checks and reporting

The parser implements only Saleae's documented digital version 0 export: the
44-byte little-endian header followed by float64 transition times. Initial state
is the level before the first listed transition; each timestamp toggles it.
It checks the identifier, version, type, initial state, exact payload size,
finite times, capture bounds, and strictly increasing transitions. All six
channel time ranges must agree. Version 1, analog files, truncated payloads,
extra bytes and corrupt timestamps explicitly produce an input error. The
version 0 format contains neither sample rate nor acquisition-gap information.
See the [official Saleae format](https://www.saleae.com/support/logic-software/saving-and-exporting-data/binary-export-format-logic-2).

Exit status is 0 for a DLD pass or a successful legacy characterization, 1 for
observed waveform violations, and 2 for malformed/unsupported input. A JSON
report is written on success and handled input errors when `--json PATH` is
supplied. The parent directory must already exist and the file must be writable;
an existing report is overwritten. Argument-parser errors happen before JSON
report generation, and an output-write failure cannot produce that report.
Legacy reports have `pass: null` and `status: "characterized"`; this is not
evidence that legacy signals satisfy DLD's waveform windows.

Raw transitions are memory-mapped and checked in chunks. Histograms include
every observation, with 5 ns bins around the symbol range and wider bins for
long delays. Minimum, maximum, mean and counts are exact up to floating-point
arithmetic. `percentile_bin_bounds_ns` reports the containing histogram bin;
these are bounds, not exact percentiles or estimates from sampled pulses.
Histogram entries are `[lower_ns, upper_ns, count]`; a null upper bound means
unbounded. A reported `numeric_roundoff_allowance_ns` handles only float64
arithmetic, not instrument accuracy or an additional engineering tolerance.

Top-level `duration_s` is the exported continuous time range. Pulse counts only
include highs with both a rising and falling edge observed. Truncated highs
are recorded separately. Counts from six channels are summed as observations;
this does not multiply capture duration into six times as much bench time.
`channels[i].violations.counts` retains all failures even after the bounded
example list fills. More than one violated property may refer to the same bit.

## Legacy characterization

Legacy mode reports high/low and inter-rise distributions without classifying
zero/one values or imposing a nominal bit period. Lows at least 50 us (adjustable
with `--reset-separator-us`) delimit generic bursts. It reports
`channels[i].complete_bursts`, `burst_length_pulses` and incomplete boundary
bursts; it does not label them validated pixel frames. Low and rising-period
distributions at every 24th pulse after an observed burst start are labeled
`pixel_boundary_*_assuming_24_bits`. Those labels state the grouping assumption,
and can expose extra spacing at pixel boundaries without validating a protocol.

## DLD validation

The configuration is the same strict `pixel_type`/six `string_lengths` JSON used
by `dld-init`. Supported profiles and byte order match the four current driver
profiles. Default complete-pulse limits are:

| Quantity | Accepted range |
|---|---:|
| Zero high | 300–400 ns |
| One high | 650–750 ns |
| Low following a zero | 800–900 ns |
| Low following a one | 450–550 ns |
| Rising-to-rising bit period | 1,150–1,250 ns |

Every complete high is checked. Every low and rising period between adjacent
bits is checked, including observable pulses inside excluded capture-boundary
fragments. A final-bit low extends through reset, so it is not tested against
the ordinary data-low window. The final high and final bit content remain
checked. Complete observed reset gaps must be at least 300 us by default.

The reset-segmentation threshold defaults to 50 us. It only determines where
bursts split. **Every interior burst must still contain exactly 24 times the
configured length.** Thus an in-frame low stall cannot be silently discarded
as a harmless reset. Sub-threshold stalls fail low/period timing; longer stalls
produce malformed frame lengths. Disabled channels must remain low throughout.

For full-frame counting at capture boundaries, leave at least **300 us low**
visible before the first rise and after the final fall. A frame cut by a capture
boundary is excluded from `channels[i].complete_frames`; its observable pulse
timing and checkable color prefix/suffix are still checked. No enabled channel
can pass with zero complete frames. `--expected-frames N` additionally requires
exactly N complete frames on each enabled channel, which detects entirely
missing or extra commands when the capture encloses the whole test. Idle time
alone cannot reveal a missing command without an external expected count.

`--colors 12AB34,000000,FFFFFF` accepts only those uniform RGB colors. Every bit
of each frame must match a single color repeated for its configured length.
`--sequence 12AB34,000000,FFFFFF` additionally validates a repeating order; the
initial captured position in that cycle may be arbitrary. Alternatively,
`--allow-any-color` decodes arbitrary RGB values while still requiring every
pixel within a frame to repeat one 24-bit word. It does not bypass content
checking. Use `--bank-order` with random colors to require agreement across the
strings and banks as well.

`--bank-order` compares **every corresponding rising and falling edge** across
the shared prefix of enabled strings in a bank (50 ns default skew), per-bank
color agreement, nonoverlapping bank streams, and the
cyclic order GPIO2 → GPIO1 → GPIO0, omitting disabled banks. Short and long
strings in the same bank must start together. It uses the longest string as
that bank's anchor and accounts for truncated boundary frames. Known-start
end-truncated frames still contribute all observable shared edges; unknown
leading fragments retain per-channel timing checks. The reported
`shared_prefix_edge_comparisons` counts the actual paired edges checked. The report's
`bank_order.complete_panel_cycles` counts only cycles containing all enabled
banks. Individual channel frames can be complete even when the capture cuts a
panel command between banks.

These checks concern digital edges at the probed inputs. They do not measure
analog voltage quality, physical LED colors or latch acknowledgment, nor prove
correctness outside the captured/exported interval.
